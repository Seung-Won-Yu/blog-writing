견적서, 회의록, 영수증을 한 번에 보낼 때마다 파일 세 개를 열고 순서를 확인한다면 이 자동화를 그대로 따라 해볼 수 있다. PDF 이름 앞에 01, 02, 03을 붙여 폴더에 넣고 스크립트를 한 번 실행하면 순서대로 합쳐진 파일이 만들어진다. 왼쪽 목록에서 각 문서의 첫 쪽으로 바로 이동하는 책갈피도 함께 생기며, 이름만 PDF인 잘못된 파일은 결과에서 빠진다.

PDF 여러 개를 순서대로 합치고 책갈피까지 만드는 방법

Python 자동화가 처음인 사람도 준비물부터 실행 결과 확인까지 따라 할 수 있게 PDF 병합 과정을 단계별로 정리했다.

먼저 결과부터: 세 파일이 한 번에 열렸다

견적서, 회의록, 영수증을 메일 한 통에 붙일 때 파일을 세 번 열게 된다. 순서까지 중요하면 01, 02, 03으로 이름을 바꾸고 제대로 놓였는지 다시 확인해야 한다. 이번 방법은 이 세 파일을 한 번에 합치고, 잘못된 파일은 결과에서 빼준다.

완성된 PDF의 왼쪽 목록에는 견적서·회의록·영수증이라는 이동 메뉴도 생긴다. 여기서 책갈피란 긴 PDF를 계속 넘기지 않고 원하는 문서의 첫 쪽으로 바로 이동하는 메뉴를 뜻한다.

준비물은 Python과 복사본 폴더 하나

  • Python 3.9 이상이 설치된 Windows 또는 macOS 컴퓨터
  • 원본이 아닌 PDF 복사본 세 개 이상
  • 메모장이나 텍스트 편집기
  • 새로 만든 pdf-merge 작업 폴더

처음 한 번만 PDF 처리 도구인 pypdf를 설치한다. Windows는 첫 줄, macOS는 둘째 줄 중 자신의 운영체제에 맞는 한 줄만 실행하면 된다. Python이 설치되어 있지 않다면 먼저 Python 공식 설치 프로그램이 필요한 방식이다.

# Windows
py -m pip install pypdf==6.16.2

# macOS
python3 -m pip install pypdf==6.16.2

1단계: 합칠 순서대로 파일명을 정한다

pdf-merge 폴더 안에 input-pdfs 폴더를 만들고 PDF 복사본을 넣는다. 프로그램은 파일명 순서대로 합치므로 앞에 01, 02, 03을 붙인다. 파일명에서 확장자를 뺀 부분은 책갈피 이름으로도 사용된다.

   └─ 03-영수증.pdf

2단계: 스크립트 전체를 그대로 붙여넣는다

메모장을 열어 아래 코드를 전부 복사하고 merge_pdfs.py라는 이름으로 저장한다. 코드를 줄마다 이해하거나 수정할 필요는 없다. 기존 업무문서-묶음.pdf가 있으면 덮어쓰지 않고 멈추도록 해두었으므로 이전 결과도 보호된다.

from pathlib import Path
from pypdf import PdfReader, PdfWriter

INPUT_DIR = Path('input-pdfs')
TEMP_FILE = Path('업무문서-묶음.tmp.pdf')
OUTPUT_FILE = Path('업무문서-묶음.pdf')

def has_pdf_header(path):
    with path.open('rb') as file:
        return file.read(5) == b'%PDF-'

valid = []
excluded = []
for path in sorted(INPUT_DIR.glob('*.pdf')):
    if not has_pdf_header(path):
        excluded.append(f'{path.name}: PDF 형식 아님')
        continue
    try:
        reader = PdfReader(str(path))
        valid.append((path, reader.metadata.title or path.stem, len(reader.pages)))
    except Exception as error:
        excluded.append(f'{path.name}: {type(error).__name__}')

if not valid:
    raise SystemExit('합칠 수 있는 PDF가 없습니다.')
if OUTPUT_FILE.exists():
    raise SystemExit('기존 업무문서-묶음.pdf를 다른 곳으로 옮긴 뒤 다시 실행하세요.')

writer = PdfWriter()
page_cursor = 0
for path, title, page_count in valid:
    writer.append(str(path))
    writer.add_outline_item(title=title, page_number=page_cursor)
    page_cursor += page_count

try:
    with TEMP_FILE.open('wb') as output:
        writer.write(output)
    merged = PdfReader(str(TEMP_FILE))
    bookmarks = [item for item in merged.outline if not isinstance(item, list)]
    if len(merged.pages) != page_cursor or len(bookmarks) != len(valid):
        raise RuntimeError('페이지 또는 책갈피 검증에 실패했습니다.')
    TEMP_FILE.replace(OUTPUT_FILE)
except Exception:
    TEMP_FILE.unlink(missing_ok=True)
    raise

print(f'완료: {OUTPUT_FILE} / {page_cursor}쪽 / 책갈피 {len(valid)}개')
if excluded:
    print('제외된 파일:')
    for reason in excluded:
        print(f'- {reason}')

이 스크립트는 먼저 파일이 실제 PDF인지 열어보고, 정상 파일만 임시 결과에 합친다. 페이지 수와 책갈피 수가 예상과 같을 때만 최종 이름을 붙인다. 입력 폴더의 PDF는 읽기만 하므로 원본 복사본은 수정하지 않는다.

3단계: 한 줄로 실행하고 결과를 확인한다

터미널이나 명령 프롬프트에서 pdf-merge 폴더로 이동한 뒤 운영체제에 맞는 한 줄을 실행한다. 성공하면 같은 폴더에 업무문서-묶음.pdf가 생기고 완료 메시지에 전체 페이지와 책갈피 수가 표시된다.

# Windows
py merge_pdfs.py

# macOS
python3 merge_pdfs.py

완성 파일을 열어 세 가지만 확인한다. 첫째, 페이지가 01·02·03 순서인지 본다. 둘째, PDF 왼쪽 책갈피를 눌렀을 때 해당 문서의 첫 쪽으로 이동하는지 확인한다. 셋째, 화면에 표시된 제외 파일이 실제로 열리지 않는 파일인지 확인한다.

깨진 파일이 섞이면 원본은 그대로 남는다

테스트에는 PDF 확장자만 붙인 일반 텍스트 파일을 하나 섞었다. 확장자만 믿고 합쳤을 때는 네 번째 파일에서 작업이 멈췄지만, 위 스크립트는 실제 PDF인지 먼저 확인해 그 파일을 제외 목록에 남기고 정상 문서 세 개만 합쳤다.

병합 도중 다른 오류가 생겨도 업무문서-묶음.tmp.pdf만 지우고 입력 PDF는 건드리지 않는다. 다만 실제 업무 자료는 권한이나 전자서명이 있을 수 있으므로 처음에는 반드시 복사본 폴더에서 시험해야 한다.

수동 작업과 자동화의 차이
작업수동 작업이 자동화
파일 순서매번 열어 확인01·02·03 이름으로 고정

실제 업무에 적용하기 전 다섯 가지만 확인한다

  • 원본이 아닌 복사본 폴더에서 첫 실행을 한다.
  • 01·02·03 파일명 순서가 원하는 결과 순서와 같은지 본다.
  • 제외된 파일은 직접 열어 실제로 문제가 있는지 확인한다.
  • 암호가 걸렸거나 전자서명이 있는 PDF는 이 방법으로 바로 합치지 않는다.
  • 업무문서-묶음.pdf를 열어 페이지와 책갈피를 확인한 뒤 전달한다.

세 파일을 한 번만 합칠 때는 수동 방식이 더 빠를 수도 있다. 하지만 월별 증빙, 회의 자료, 견적서 묶음처럼 같은 순서와 규칙이 반복된다면 다음 달부터는 입력 폴더의 파일만 바꾸고 다시 실행할 수 있다.

개발 기록: 어디까지 직접 확인했나

실제 업무 문서는 사용하지 않고 제목만 있는 1쪽짜리 견적서·회의록·영수증과 이름만 PDF인 잘못된 파일을 만들어 시험했다. Python 3.9.6과 pypdf 6.16.2에서 네 입력 중 정상 세 개가 3쪽으로 합쳐졌고 책갈피 세 개의 이동 위치도 일치했다.

파일 이름만 바꾼 일반 텍스트는 병합 전에 제외됐다. 파일 내부가 더 심하게 손상됐을 때도 읽는 단계에서 오류로 분류되며, 최종 파일을 만들기 전 임시 결과가 제거되도록 확인했다.

암호화 PDF, 입력 양식이 있는 PDF, 전자서명 문서, 수백 쪽짜리 큰 파일은 이번 실험 범위에 포함하지 않았다. 이런 문서는 복사본으로 서명과 양식이 유지되는지 별도로 확인해야 한다.

좋은 자동화는 코드를 많이 보여주는 글이 아니라, 처음 보는 사람도 준비부터 결과 확인까지 혼자 끝낼 수 있게 만드는 도구다.

이번 자동화는 PDF를 단순히 한 파일로 합치는 데서 끝나지 않는다. 파일명 순서를 지키고, 열 수 없는 입력은 제외하고, 완성된 문서에 이동용 책갈피가 생겼는지 다시 확인한다. 테스트에서는 견적서·회의록·영수증 세 개가 3쪽짜리 한 파일로 합쳐졌고 잘못된 한 파일은 제외됐다. 매달 같은 형식의 증빙이나 회의 자료를 정리한다면 코드를 수정하지 않고 입력 폴더의 파일만 바꿔 다시 사용할 수 있다. 처음에는 실제 원본이 아닌 복사본 세 개로 실행하고, 완성된 PDF의 페이지 순서와 왼쪽 책갈피를 확인한 뒤 업무 폴더에 적용한다.
