Claude도 PDF 질문을 받지만 입력 계약은 따로 읽는다

Anthropic의 PDF support 문서는 PDF의 텍스트·그림·차트·표를 질문 대상으로 설명한다. 문서 URL, base64 데이터, Files API 참조가 제시되지만 사용 플랫폼별 지원 방식이 같다고 가정해서는 안 된다.

암호가 걸린 파일을 일반 PDF 입력과 같은 것으로 취급하지 않는다. 페이지 수와 요청 크기처럼 바뀔 수 있는 제한은 선택한 모델·플랫폼의 현재 문서에서 확인한다. 다른 입력이 함께 실리면 PDF 파일 크기만 보고 전체 요청의 적합성을 판단하기 어렵다.

두 서비스 모두 PDF를 받는다는 이유만으로 한국어 문서의 숫자·표·도표에서 동일한 정확도를 낸다고 말할 수 없다. 이 글은 같은 문서를 넣은 비교 실행을 하지 않았으므로 성능이나 비용의 승자를 정하지 않는다. 먼저 필요한 입력 계약을 충족하는 후보만 남긴다.

OCR을 생략할 수 있는 경우와 남겨 둘 경우

pypdf 문서는 텍스트 추출을 제공하지만 이미지뿐인 페이지에서 글자를 인식하는 OCR 도구는 아니다. 기존 문자열이 필요한 검색 파이프라인과 PDF 화면을 바로 질문하는 경로를 한 가지 처리로 묶지 말자.

AI 응답이 아닌 검색 가능한 PDF 사본을 남겨야 한다면 텍스트 레이어를 만드는 OCR 경로가 여전히 목적에 맞는다. 반면 그림의 의미를 묻는 과제에서 먼저 모든 페이지를 문자열로 바꾸는 것이 필수라고 단정할 이유는 없다. 서비스의 실제 PDF 입력 방식을 확인한 뒤 필요한 전처리만 정한다.

스캔한 표의 숫자를 읽고 합계까지 답하게 할 때는 두 문제가 이어진다. 글자를 틀리게 읽는 오류와, 읽은 수치를 잘못 연결하거나 계산하는 오류다. 입력 방식만 교체하고 최종 합계만 확인하면 어느 단계의 문제인지 찾기 어렵다.

대표 질문에 근거 페이지를 붙여 선택을 끝낸다

  • 공개 자료나 합성 문서에서 본문·표·차트 대표 페이지를 고른다.
  • 각 질문의 정답 근거와 페이지 번호를 사람이 먼저 적는다.
  • 답이 없는 질문도 포함해 근거 없는 추정과 보류를 구분한다.
  • 응답과 원문을 대조하고 누락·숫자·표 대응 오류를 따로 기록한다.

예를 들어 “표에서 모델 A의 최대 입력은 얼마인가”라는 질문이라면 값만 적지 말고 단위와 행·열 제목을 함께 정답 근거에 넣는다. 차트 조건을 묻는다면 본문이나 각주의 조건 문장도 포함한다. 이 목록은 실행 결과가 아니라 후보를 시험할 평가 설계다.

공식 문서를 대조한 이 글의 판단은, 제품 이름보다 필요한 결과와 근거 대조 방식을 먼저 정하면 PDF 화면 이해와 텍스트 추출을 구분해 선택할 수 있다는 것이다.

한 문서의 성공을 전체 문서 유형의 성공으로 일반화하지 않는다. 스캔 화질과 레이아웃이 바뀌면 같은 질문 유형도 다시 대조한다. 입력 한도에 맞추기 위해 파일을 나눴다면 질문에 필요한 다른 페이지가 빠졌는지도 기록한다.

근거와 한계

공식 문서를 대조한 선택 가이드이며 API 호출과 한국어 정확도·비용·속도 비교는 실행하지 않았다.

2026년 11월 20일 Google·Anthropic·pypdf의 공식 문서를 확인했다. 개인 문서 업로드나 유료 API 실행은 하지 않았다. 문서 지원 기능을 비교한 것으로 제품 사용 후기나 한국어 인식률 순위는 아니다.

선택한 입력 경로와 대표 질문, 근거 페이지 및 숫자 대조 결과가 기록되어야 한다.
