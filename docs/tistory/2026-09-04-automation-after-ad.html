고정: 매번 필요한 규칙만 짧게 둔다

저장소의 언어, 테스트 명령, 편집 금지 경로, 완료 기준처럼 대부분의 작업에 반복되는 규칙은 고정 지침에 둔다. 반대로 이번 버그의 재현 로그나 임시 파일 이름은 고정하지 않는다. 영구 규칙과 일회성 요청을 섞으면 오래된 예외가 다음 작업까지 따라온다.

OpenAI의 현재 모델 지침도 반복되는 지시와 예시를 줄이고 각 지시를 한 번만 명확하게 말하라고 권한다. 같은 뜻을 여러 표현으로 겹치면 강조가 아니라 충돌 가능성이 생긴다. 고정 규칙을 추가할 때는 기존 문장과 합칠 수 있는지부터 확인한다.

목표: 로그인 실패를 재현하고 원인만 보고한다.
범위: auth 모듈과 관련 테스트를 읽는다.
중단: 운영 데이터 변경이나 외부 전송이 필요하면 멈춘다.
완료: 재현 명령, 관찰 결과, 가장 유력한 원인을 남긴다.

찾기: 큰 자료는 필요한 순간에만 연다

설계 문서 수십 개, 저장소 전체, 긴 CI 로그를 처음부터 붙이지 말고 어디에서 찾을지를 알려 준다. 에이전트는 파일 목록이나 검색 결과로 범위를 좁힌 뒤 관련 구간만 읽을 수 있다. 이 점진적 공개 방식은 필요한 근거를 버리지 않으면서 초기 입력의 잡음을 줄인다.

검색이 잘 되려면 자료의 이름과 경계가 보여야 한다. 예를 들어 인증 정책은 한 문서, 배포 절차는 다른 문서로 나누고, 저장소 지도에 각 위치와 용도를 적는다. 반대로 여러 주제가 한 거대한 파일에 섞여 있으면 필요할 때 찾는 비용이 다시 커진다.

기록: 긴 대화는 결정과 남은 일로 압축한다

세션이 길어지면 원문을 모두 보존하는 대신 무엇을 결정했고, 어떤 근거를 썼으며, 무엇이 남았는지를 구조화해 기록한다. GitHub는 긴 대화를 압축하고 문제를 바꿀 때 새 대화를 시작해 컨텍스트를 가볍게 유지하라고 안내한다.

세션을 이어 갈지 새로 시작할지 판단하는 신호
상태권장 행동남길 정보
같은 목표를 수정 중현재 세션 유지최신 요구와 실패 결과
문제가 다른 축으로 전환새 대화 시작필요한 배경 링크
대화가 길고 반복이 많음결정 기록 후 압축선택 이유와 남은 일
독립 자료 조사가 필요별도 작업으로 분리질문과 반환 형식

분리: 독립적인 조사만 별도 작업으로 보낸다

라이브러리 비교, 로그 분석, 문서 조사처럼 서로 기다리지 않고 끝낼 수 있는 축은 분리하면 각 작업의 컨텍스트가 작아진다. 별도 작업에는 질문 하나, 참고할 경로, 기대하는 근거 묶음을 준다. 결과로는 결론과 출처, 불확실성만 받아 현재 작업에 합친다.

분리는 의존성을 숨기는 수단이 아니다. 같은 파일을 동시에 고쳐야 하거나 첫 결과가 있어야 다음 판단을 할 수 있다면 순차로 진행한다. 작업을 너무 잘게 나누면 설명과 통합 비용이 절약한 컨텍스트보다 커질 수 있다. 독립성과 반환 형식이 분명할 때만 쓴다.

무엇을 뺄지는 같은 작업으로 검증한다

컨텍스트를 정리한 뒤에는 느낌으로 성공을 판단하지 않는다. 이전과 같은 대표 작업을 다시 실행해 정답성, 수정 범위, 테스트 결과를 비교한다. OpenAI 지침도 지시 묶음을 하나씩 제거하고 평가를 다시 돌리는 방식을 권한다. 이 절차가 있어야 중요한 근거를 실수로 지우지 않는다.

  • 대표 작업 하나와 기대 결과를 고정한다.
  • 중복 지시나 오래된 로그 한 묶음만 제거한다.
  • 같은 모델·도구·입력으로 다시 실행한다.
  • 정답성, 수정 파일, 테스트 결과를 이전 실행과 비교한다.
  • 품질이 떨어지면 제거한 근거를 더 짧고 명확한 형태로 되돌린다.

도구 목록도 같은 방식으로 줄인다. 현재 작업에서 쓰지 않을 브라우저, 데이터베이스, 배포 도구가 노출돼 있으면 선택지가 늘고 호출 설명도 입력을 차지한다. 필요한 도구만 남긴 뒤 동일한 작업을 실행해 성공률과 불필요한 호출이 줄었는지 확인한다.

오늘 할 일: 잡음 하나만 덜어 낸다

현재 대화에서 이미 끝난 조사 로그 하나를 고른다. 원문 대신 결정, 근거, 남은 일을 세 줄로 적고 로그를 제외한다. 그런 다음 같은 테스트나 검증 명령을 다시 실행해 결과가 유지되는지 본다. 이 작은 전후 비교가 팀의 컨텍스트 규칙을 만드는 첫 근거가 된다.

결과가 같다면 다음에는 큰 문서를 검색 대상으로 옮기고, 서로 충돌하는 고정 규칙을 하나로 합친다. 결과가 나빠졌다면 빠진 근거가 무엇인지 기록해 더 짧은 형태로 되돌린다. 목표는 입력 길이 자체가 아니라 현재 판단에 필요한 신호를 선명하게 만드는 것이다.
