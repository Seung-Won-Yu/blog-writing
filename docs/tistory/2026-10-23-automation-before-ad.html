uv run·uvx 차이: AI가 만든 파이썬 스크립트 실행 기준

실행 대상·환경·보존 파일로 uv run과 uvx의 선택을 나눈다.

내 파일인가, 이미 배포된 명령인가

내 파일을 실행하려면 uv run, 배포된 명령줄 도구를 따로 호출하려면 uvx를 검토한다. 프로젝트의 코드·의존성이 필요한 작업은 그 프로젝트 환경에서 실행하고, 독립 스크립트는 필요한 패키지를 파일에 함께 기록한다.

  • 실행 대상이 직접 저장한 .py 파일인지 배포된 도구 명령인지 구분한다.
  • 프로젝트 코드와 패키지가 필요한지 확인해 독립 실행과 프로젝트 실행을 나눈다.
  • 다시 돌릴 작업은 의존성 선언·잠금 파일·실행 위치를 함께 남긴다.

가령 AI에게 CSV 보고서 코드를 받아 report.py로 저장했다고 하자. 이 파일을 실행하는 일과 Ruff라는 배포 도구로 문법을 검사하는 일은 대상부터 다르다. 이는 실제 실행 사례가 아니라 명령을 고르기 위한 가상 장면이다.

같은 폴더에 있다고 같은 패키지를 쓰는 것은 아니다. 폴더는 입력 파일을 찾는 위치가 될 수 있지만, Python이 import할 패키지의 환경은 실행 방식에 따라 달라진다. “파일이 여기 있으니 패키지도 보일 것”이라는 추정을 먼저 걷어 낸다.

uvx의 분리는 프로젝트 패키지도 가린다

Using tools 문서는 uvx가 uv tool run의 별칭이라고 설명한다. 대상은 명령줄 인터페이스를 제공하는 패키지다. uvx는 그 도구용 환경에서 실행하므로 작업 프로젝트의 패키지를 자동으로 공유하는 경로가 아니다.

그래서 문서는 프로젝트 설치가 필요한 pytest·mypy 작업이라면 uv run을 보라고 안내한다. 반대로 프로젝트 설치 없이 파일만 검사할 수 있는 경우에는 uvx가 가능하다는 예외도 둔다. 도구 이름 하나로 항상 어느 명령이라고 외우면 이 조건을 놓친다.

AI가 테스트 명령을 제시했다면 먼저 “이 테스트가 내 패키지를 import하는가”를 확인하자. 파일 모양만 검사하는 도구인지, 설치된 프로젝트를 읽고 실행하는 도구인지에 따라 필요한 환경이 바뀐다. 테스트 도구 자체도 프로젝트에 선언되어 있어야 같은 버전을 공유하기 쉽다.

패키지 이름과 실행 명령이 다를 수도 있다. Using tools는 --from으로 제공 패키지를 지정하는 방식을 안내한다. 명령을 못 찾았다고 비슷한 이름의 패키지를 추측해 설치하기보다 공식 배포 문서에서 두 이름의 관계부터 확인한다.

Tools 개념 문서에 따르면 uvx 환경은 캐시에 재사용될 수 있고 삭제되면 다시 만들어진다. 일회 호출이라는 표현을 “매번 아무것도 남기지 않는다”로 읽지 않는다. 캐시 경로 자체를 팀의 실행 조건 기록으로 삼는 것도 적합하지 않다.
