OCR 언어와 입력 품질부터 확인한다

한국어와 영어가 섞인 문서라면 언어 설정과 필요한 언어 데이터가 준비됐는지 먼저 확인한다. OCRmyPDF Cookbook은 지정 언어용 팩이 설치되어야 한다고 설명한다. 언어 이름 하나를 추가했다고 해당 문서의 인식이 정확해졌다고 판단할 수는 없다.

Tesseract 품질 가이드는 기울어진 줄, 잡음, 글자 크기와 페이지 분할 같은 입력 조건을 다룬다. 특히 표는 별도 분할·레이아웃 분석 없이 제대로 인식하기 어렵다고 명시한다. 엔진 교체에 앞서 실패한 페이지의 시각적 조건을 남길 이유다.

  • 원본 PDF는 보존하고 별도 출력 사본을 검토 대상으로 둔다.
  • 언어·회전·기울기 중 바꾼 조건을 기록하고 같은 페이지에서 결과를 대조한다.
  • 숫자나 열 대응이 중요한 문서는 문장이 나왔다는 이유만으로 다음 단계에 넘기지 않는다.

기존 텍스트를 건너뛸지, 기존 OCR을 다시 할지, 전체 페이지를 강제로 이미지화할지는 서로 다른 선택이다. 기존 OCR이 틀렸는데 단순 건너뛰기만 하면 오인식은 남는다. 반대로 강제 재처리는 벡터·시각 품질에 영향을 줄 수 있어 기본 복구 버튼으로 삼기 어렵다.

이 글은 명령을 실행하지 않았으므로 특정 옵션 조합을 검증된 처방으로 제시하지 않는다. 사용할 버전의 Cookbook에서 기존 텍스트 처리와 출력 보존 조건을 읽고, 문제가 있는 사본에서만 검토 범위를 정한다.

혼합 PDF에서는 sidecar 파일이 전체 원문이 아니다

디지털 문서 몇 장에 스캔 부록이 붙은 PDF는 특별한 경우가 아니다. 개발자가 인식 후 얻은 텍스트 파일 하나를 전체 원문으로 취급하면, 오히려 이미 읽을 수 있던 페이지를 빼먹을 수 있다. OCR 완료와 전체 본문 확보는 다른 완료 조건이다.

OCRmyPDF의 sidecar는 OCR로 찾은 텍스트를 따로 저장하는 보조 파일이다. Cookbook은 이미 텍스트가 있는 페이지의 글자는 그 파일에 들어가지 않는다고 설명한다. 페이지 선택·크기 제한·시간 초과 등으로 건너뛴 페이지도 빠질 수 있다.

가령 첫 페이지는 디지털 안내문이고 둘째 페이지는 스캔 부록인 문서를 생각해 보자. OCR이 필요한 둘째 페이지의 텍스트만 보조 파일에 남는 경로라면, 그 파일만 요약기에 넣을 때 첫 페이지는 입력에서 사라진다. 이 두 페이지 사례는 문서 규칙을 적용한 가상 예시다.

공식 Cookbook은 OCR 여부와 관계없이 PDF 전체의 텍스트가 필요하면 pdftotext 같은 추출 도구를 사용하라고 안내한다. 그러므로 전체 원문 확보가 목적일 때는 최종 PDF에서 전체 텍스트를 다시 읽는 경로와 페이지별 확인을 함께 설계할 수 있다.

  • 보조 파일의 글자 수 대신 최종 PDF의 페이지 목록과 처리 기록을 맞춘다.
  • 기존 텍스트 페이지와 OCR 페이지에서 대표 문장을 하나씩 대조한다.
  • 건너뛰기·시간 초과가 있으면 빈 결과와 정상 빈 페이지를 구분해 검토 대기 상태로 둔다.

여기서 페이지 수가 맞는다는 사실도 충분하지 않다. 모든 페이지의 문자열 항목이 있어도 본문이 누락될 수 있다. 필요한 근거 문장을 실제로 찾을 수 있는지 확인해야 “파일은 생성됐지만 답은 없다”는 다음 단계의 실패를 줄인다.

텍스트가 나와도 표와 읽기 순서는 다시 본다

W3C PDF7은 OCR 뒤 텍스트가 완전하고 올바른 읽기 순서인지 확인하는 절차를 제시한다. 화면 낭독, 텍스트 저장, 변환 내용 확인 같은 방법이다. 이 안내는 접근성 맥락이며 AI 정확도를 보장하는 규칙은 아니지만 입력 검수에도 참고할 수 있다.

두 단의 문서가 줄마다 왼쪽·오른쪽을 섞어 읽히면 모든 단어가 있어도 문장 의미가 바뀐다. 표의 품목과 금액이 서로 다른 줄로 떨어져도 마찬가지다. 인식할 글자가 있는 문제와 그 글자의 관계를 복원하는 문제를 나눠 보자.

AI에 넘길 준비가 끝났는지 판단하는 검수 기록
기록 항목확인할 예문제가 남을 때
본문 완전성필수 근거 문장이 존재함누락 페이지 재검토

표의 대응항목과 수치가 같은 행에 연결됨표 추출·수동 확인 분리

표가 핵심인 업무라면 일반 텍스트 문자열을 얻는 것만 목표로 잡지 않는다. 행·열 관계가 필요한지, 셀 좌표나 구조화 결과를 보존해야 하는지부터 정한다. 이 글은 특정 표 추출기의 우열을 평가하지 않으며 추가 도구는 실제 실패한 표를 기준으로 비교해야 한다.

AI가 그럴듯하게 요약했다고 이 검사를 대신할 수도 없다. 입력에서 빠진 페이지를 모델이 모르는 상태와, 입력은 맞지만 해석이 잘못된 상태를 분리해야 수정할 곳이 보인다. 문제의 원문 페이지와 추출 문자열을 함께 남기면 후속 디버깅이 쉬워진다.

여러 공식 문서를 연결한 이 글의 해석은, PDF 전체에 도구 하나를 고정하기보다 페이지의 텍스트 상태와 필요한 결과에 따라 추출·OCR·검토를 나누는 편이 누락을 찾기 쉽다는 것이다.

  • 검수한 페이지·문장과 아직 확인하지 않은 범위를 함께 적는다.
  • 정상 추출·OCR 필요·검토 대기를 구분하고 검토 대기는 자동 성공으로 바꾸지 않는다.
  • 텍스트 처리 조건이 바뀌면 같은 대표 페이지와 문장으로 다시 확인한다.

근거와 한계: 한국어 성능 순위를 매기지 않았다

확인일은 2026년 10월 16일이다. pypdf의 추출 범위, OCRmyPDF의 PDF 처리와 보조 출력, Tesseract의 입력 품질, W3C의 사후 확인 절차를 읽었다. 공식 문서 다섯 URL은 서로 다른 역할을 설명하며 동일 문서를 대상으로 한 비교 실험은 아니다.

이 글은 공식 문서 다섯 곳을 대조한 선택 가이드다. PDF 추출기나 OCR 엔진을 설치·실행하지 않았으며, 한국어 인식률·표 복원 성능·처리 속도를 측정하지 않았다.

선택을 마쳤다는 신호는 OCR 프로그램 종료나 텍스트 파일 생성만이 아니다. 필요한 페이지의 근거 문장이 있고, 중요한 숫자와 문단·표의 관계가 맞으며, 미확인 페이지가 구분되어 있어야 한다. 그 조건을 남긴 뒤 다음 AI 처리 단계를 연결한다.

  • 추출기·OCR 버전이나 언어 데이터를 바꾸면 같은 페이지에서 다시 확인한다.
  • 새 문서 유형이나 표·다단 편집이 들어오면 기존 선택표가 맞는지 점검한다.
  • 멀티모달 입력으로 경로를 바꾸면 그 서비스의 PDF 처리·제한을 별도로 확인한다.
