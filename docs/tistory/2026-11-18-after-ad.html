running은 재개 후보를 찾는 첫 단서다

원래 검사 환경에서 기록을 먼저 읽는다. 명령에서 SCAN_ID는 목록의 실제 ID로 바꾼다. 화면에 재개 명령이 나오더라도 원래 프로세스가 아직 살아 있으면 종료를 기다리고 기록을 확인한다.

원래 프로세스가 실행 중기존 작업을 지켜보고 별도 실행을 보류한다.
중단됐고 running으로 남음원래 체크아웃·상태·출력 폴더·세션이 살아 있고 재개 안내가 나오면 codex-security scans resume SCAN_ID로 이어간다.
failed 또는 canceled접근 오류나 취소 사유를 확인한다. 저장된 실행 설정이 있으면 scans rerun으로 새 검사를 시작할 수 있다.
completed저장된 보고서에서 대상 코드와 제외 범위를 확인한다.

SDK 앱에는 검사 ID와 결과 경로를 남긴다

SDK에서는 onReconnect로 연결 재시도를 기록할 수 있다. 0.10.0 구현은 일부 연결 오류에서 복구 명령과 출력 폴더가 담긴 ScanInterruptedError를 돌려준다. SDK 문서의 취소 예제도 같은 오류 타입으로 부분 출력 위치를 알려 준다. 오류 이름만으로 재개를 결정하지 말고 검사 이력의 상태와 재개 안내를 확인한다.

앱의 작업 기록에 검사 ID와 비공개 출력 위치를 연결해 두면 운영자가 기존 상태를 먼저 볼 수 있다. 결과 폴더에는 코드 발췌나 재현 정보가 포함될 수 있으므로 열람을 제한한다. 새 CI 러너에서 보고서 파일만 되가져오는 구성은 원래 세션을 이어갈 수 없다. 예전 버전에서 실패로 닫힌 검사나 커스텀 검증 검사는 새 실행을 검토한다.

다시 연결된 뒤에는 검사 범위까지 읽는다

보고서가 나오면 scan-manifest.json의 검사 상태와 범위, 제외 경로를 확인한다. 이전에 남은 부분 결과를 최종 보고서로 넘기면 조사하지 않은 경로가 빠질 수 있다. 공개 릴리스와 구현 변경을 대조한 절차다. 실제 저장소를 스캔하거나 복구 동작과 비용을 실측하지 않았다.

함께 읽기

이어서 보면 좋은 글

  • Codex Security 오픈소스 공개: 설치보다 먼저 확인할 접근권한과 CI 기준검사를 시작하기 전 필요한 접근 조건과 비공개 결과 보관 기준을 확인할 수 있다.
  • AI 모델 평가가 운영망을 넘었다면: 샌드박스에 추가해야 할 4가지 경계검사 도구가 작업하는 환경에서 자격증명과 운영망 접근 범위를 검토할 때 참고할 수 있다.

검사를 운영하는 쪽에서는 앱의 요청 상태와 보안 도구의 검사 상태를 따로 기록해 두면 복구가 쉽다. 앱이 응답을 받지 못했어도 기존 검사가 살아 있을 수 있고, 재개한 검사가 종료돼도 일부 경로가 빠져 있을 수 있다. 이 두 상태를 구분하면 불필요한 중복 검사와 검토 누락을 함께 줄일 수 있다. 같은 검사 ID에 완료 기록이 생기고, 저장된 보고서의 검사 범위와 제외 경로까지 확인하면 복구 처리를 마친다.
