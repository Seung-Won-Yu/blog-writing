AI 코딩 에이전트가 빨리 실패하는 장면은 대개 비슷하다. 취소 주문을 빼 달라는 한 줄을 보자마자 코드를 고치지만, 취소 상태가 어떤 문자열인지와 환불 주문을 어떻게 볼지는 확인하지 않는다. 인기 스킬 저장소가 실제로 이 성급함을 막는지 확인하려고 같은 작은 Python 저장소와 같은 모호한 요구사항을 Superpowers, mattpocock/skills, Karpathy Guidelines에 각각 넣었다. 세 실행 모두 코드를 한 줄도 바꾸지 않고 멈췄지만, 멈추는 방식은 확실히 달랐다.

업무자동화 실험

실행 기록 · 요즘IT · 2026. 8. 12

AI 에이전트 스킬 저장소, 같은 코딩 과제로 비교해 보니

인기 에이전트 스킬 저장소의 설계 철학을 소개한 글을 바탕으로 세 저장소를 같은 읽기 전용 과제에 직접 적용했다.

별점 대신 같은 모호한 과제를 건넸다

요즘IT 글은 인기 스킬 저장소가 단순 프롬프트 모음이 아니라 에이전트에게 일하는 절차를 가르치는 온보딩 문서라고 설명한다. 순위는 발견에 도움이 되지만 내 작업에 맞는지는 알려 주지 않는다. 그래서 기능 목록을 다시 요약하는 대신 세 저장소의 핵심 규칙을 고정한 뒤 동일한 작은 Python 과제에 적용했다.

fixture에는 주문 목록의 합계를 계산하는 total_amount 함수와 테스트가 있다. 요구사항은 ‘취소 주문을 합계에서 제외하라’ 한 줄뿐이다. 어떤 문자열을 취소로 볼지, 환불된 주문까지 제외할지는 쓰지 않았다. 좋은 첫 행동은 그 빈칸을 확인하는 것이고, 나쁜 첫 행동은 임의의 문자열을 정해 바로 코드를 바꾸는 것이다.

과제: total_amount가 취소 주문을 제외하도록 수정한다.
제약: 첫 응답만 작성하고 파일은 변경하지 않는다.
일부러 비운 조건: 취소 상태 문자열, 환불 주문 처리

세 저장소는 규모보다 통제 방식이 달랐다

실험 커밋에서 Superpowers는 14개의 SKILL.md를 갖고 있었고, 브레인스토밍 스킬은 요구가 명확해 보이더라도 질문과 설계 승인 전에는 구현하지 않는 하드 게이트를 둔다. mattpocock/skills는 35개의 스킬로 더 잘게 나뉘며, grilling은 남은 결정을 번호로 한꺼번에 제시하고 각 항목에 추천안을 붙인다. Karpathy Guidelines는 하나의 짧은 스킬에 가정 확인, 최소 변경, 테스트 목표를 묶는다.

라이선스도 같지 않다. 확인 시점에 Superpowers와 mattpocock/skills는 MIT 라이선스를 표시했지만 Karpathy 파생 저장소는 GitHub 메타데이터에서 감지된 라이선스가 없었다. Karpathy가 직접 만들거나 보증한 저장소가 아니라는 안내도 읽어야 한다. 팀 공통 규칙으로 복사할 계획이라면 인기보다 출처와 라이선스를 먼저 확인해야 한다.

같은 첫 응답인데 질문의 폭이 달랐다

세 실행은 같은 gpt-5.6-terra medium, 읽기 전용 sandbox, 임시 세션에서 수행했다. 스킬 파일과 과제 파일만 읽게 했고 첫 응답 뒤 종료했다. 결과는 세 경우 모두 git diff가 비어 있었다. 스킬을 붙였다는 사실보다 ‘코드를 바꾸지 않았다’는 행동이 먼저 확인됐다.
