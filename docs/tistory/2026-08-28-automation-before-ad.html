견적서, 회의록, 영수증을 한 번에 전달하려고 파일을 하나씩 열고 순서를 맞추는 작업은 작지만 자주 반복된다. 네 개의 테스트 파일을 자동 병합했더니 이름만 .pdf인 한 파일에서 작업이 멈췄다. 불완전한 출력은 지우고 실제 PDF 헤더가 있는 세 문서만 다시 묶었다. 결과는 3쪽짜리 한 파일과 각 문서의 첫 쪽으로 이동하는 책갈피 3개였다.

업무자동화 실험

실행 기록 · pypdf 공식 문서 · 2026. 8. 23

PDF 합치기와 문서별 책갈피 자동 생성 실험

pypdf 6.16.2로 합성 업무 PDF 세 개를 순서대로 병합하고, 이름만 PDF인 입력을 제외한 뒤 문서별 책갈피 목적지를 다시 읽어 검증했다.

네 문서 중 하나가 이름만 PDF였다

견적서, 회의록, 영수증을 메일 한 통에 붙일 때 받는 사람이 열어야 할 파일도 세 개가 된다. 순서가 중요한 자료라면 파일명을 01, 02, 03으로 바꾸고 다시 확인하는 손동작까지 반복된다.

이번 실험은 실제 업무 자료를 쓰지 않았다. ReportLab으로 제목과 금액만 있는 합성 PDF 세 개를 만들고, 네 번째 파일에는 PDF 확장자만 붙인 일반 텍스트를 넣었다. 입력은 모두 임시 폴더에 두었다.

완료 기준은 세 가지로 정했다. 유효한 문서만 파일명 순서대로 한 PDF가 되고, 각 문서 제목이 책갈피로 남으며, 잘못된 입력에서 실패해도 불완전한 최종 파일을 남기지 않아야 한다.

pypdf 6.16.2와 실행 범위를 먼저 고정했다

공식 README에서 pypdf는 분할·병합·변환을 지원하는 순수 Python PDF 라이브러리로 설명된다. 6.16.2의 최소 Python은 3.9이며 기본 설치에서는 Python 3.11 미만에 typing_extensions만 요구한다.

실험 환경은 macOS 26.6.2, Python 3.9.6, pypdf 6.16.2, ReportLab 4.4.10이다. pypdf 공식 태그의 소스 커밋은 1da09878621e5286e00510e4d378dfdf8940e541로 고정했다.

공식 병합 문서는 PdfWriter.append로 파일 전체를 이어 붙이는 방식을 권한다. 책갈피 문서는 add_outline_item에 제목과 0부터 시작하는 페이지 번호를 넘기는 예제를 제공한다. 두 API를 한 반복문에 연결했다.

파일명 순서와 시작 쪽을 같은 반복문에서 기록했다

입력은 sorted로 파일명 순서를 고정했다. 각 PDF를 읽기 직전 현재 page_cursor를 기억하고, 병합 뒤 페이지 수만큼 커서를 늘렸다. 책갈피 목적지는 문서가 추가되기 전의 커서 값이다.

from pathlib import Path
from pypdf import PdfReader, PdfWriter

def is_pdf(path):
    with path.open('rb') as f:
        return f.read(5) == b'%PDF-'

inputs = sorted(Path('input-pdfs').glob('*.pdf'))
valid = [path for path in inputs if is_pdf(path)]
writer = PdfWriter()
page_cursor = 0

for path in valid:
    reader = PdfReader(path)
    title = reader.metadata.title or path.stem
    writer.append(reader)
    writer.add_outline_item(title=title, page_number=page_cursor)
    page_cursor += len(reader.pages)

with open('업무문서-묶음.tmp.pdf', 'wb') as output:
    writer.write(output)

코드는 .pdf라는 이름보다 파일 첫 다섯 바이트를 먼저 본다. %PDF-가 없으면 병합 대상에서 빼고 제외 목록에 남긴다. 이 검사는 모든 손상을 증명하지는 않지만 일반 텍스트를 PDF로 오인하는 실수는 앞에서 막는다.

출력은 곧바로 최종 이름에 쓰지 않았다. 업무문서-묶음.tmp.pdf에 먼저 저장하고, 다시 열어 페이지 수와 책갈피를 검사한 뒤에만 업무문서-묶음.pdf로 이름을 바꾸도록 했다.

이 순서는 입력 파일을 수정하지 않는다. 실패하면 임시 출력과 불완전한 최종 파일만 제거하고 견적서·회의록·영수증 원본은 그대로 남는다. 실제 문서에서도 원본을 복사한 폴더에서 먼저 실행하는 편이 안전하다.
