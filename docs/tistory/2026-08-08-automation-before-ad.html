im-not-ai 사용법: AI 글투 진단과 변경률 가드 직접 실험

im-not-ai v2.3.0의 라우팅과 변경률 검사 스크립트를 합성 한국어 문장에 실행해 수정 강도와 강제 중단 기준을 확인했다.

문장이 매끄러운데 내 글은 아닌 순간

AI 초안을 다듬을 때 가장 눈에 띄는 문제는 안전한 결론 전환어, 양면을 맞추는 문장, 과장된 평가 표현이 반복되는 것이다. 이런 말을 지우는 일은 어렵지 않다. 더 어려운 문제는 문장이 자연스러워지는 동안 원래 주장과 사실도 조금씩 바뀌는 것이다. 블로그 글이라면 글쓴이의 경험이 사라지고, 업무 문서라면 숫자와 책임 범위가 흐려질 수 있다. 자연스러움만 점수로 삼으면 많이 고친 결과가 더 좋아 보이는 함정이 생긴다.

im-not-ai는 한국어 번역투, 기계적인 병렬, 피동 표현, 과도한 불릿과 접속사 등을 분류한 오픈소스 프로젝트다. README는 의미·사실·수치·고유명사를 유지하고 탐지된 구간만 고치며, 변경률이 30%를 넘으면 경고하고 50% 이상이면 중단하는 원칙을 내세운다. 이름만 보면 AI 판별기처럼 느껴질 수 있지만 이번에 실행한 코드는 글쓴이가 사람인지 AI인지 판정하지 않았다. 문장 신호를 세어 수정 경로를 추천하고, 수정 전후가 얼마나 달라졌는지를 계산했다.

설치하지 않고 결정적 스크립트만 꺼냈다

여기서 재현할 것은 AI 윤문 품질이 아니라 입력 진단과 변경률 게이트다. 2026년 8월 8일 실험에 사용한 v2.3.0 태그를 그대로 고정한다. 원래 실험은 Python 3.9.6에서 수행했으며, 아래 보완 절차는 2026년 10월 13일 Python 3.14.4에서 별도 합성 문장으로 확인했다.

  • Git과 Python 3가 실행되는 macOS·Linux 터미널을 준비한다. Windows에서는 WSL의 같은 셸 예제로 따라 한다.
  • 원문과 수정본은 개인정보 없는 UTF-8 텍스트로 준비한다. 원본 문서를 덮어쓰지 않는다.
  • 아래 작업 폴더 이름이 이미 있으면 새 이름으로 바꾼다. 전역 스킬 설치와 API 키는 이 진단 실습에 필요하지 않다.
git clone --depth 1 --branch v2.3.0 https://github.com/epoko77-ai/im-not-ai.git im-not-ai-v230-test
cd im-not-ai-v230-test

이후 명령은 복제한 저장소 안에서 실행한다. sample 폴더에 01_input.txt라는 이름의 원문이 있어야 한다. --run-dir만 지정하면 폴더는 만들어져도 입력 내용은 생기지 않는다. 아래는 복사 가능한 합성 예시이며 실제 업무 경험을 기록한 문장이 아니다.

mkdir sample
cat > sample/01_input.txt <<'EOF'
생성형 AI는 업무 효율성을 향상시키는 혁신적인 도구입니다. 다만 결과에는 문제가 존재할 수 있다.
EOF
cat > sample/after.txt <<'EOF'
생성형 AI는 업무 효율성을 높이는 혁신적인 도구입니다. 다만 결과에는 문제는 남을 수 있다.
EOF
python3 scripts/prepare_monolith_input.py --run-dir sample --genre blog
python3 scripts/verify_change_rate.py --before sample/01_input.txt --after sample/after.txt

첫 명령이 끝나면 sample 안에 00_metrics.json과 01_input_with_metrics.txt가 생긴다. 01_input.txt는 그대로 남는다. 보완 예시는 route_hint=light, degraded=False였고 두 번째 명령은 변경률 12.1%·OK를 출력했다. 아래 기존 실험의 22.5%와는 입력이 다른 별도 확인이다.

WARN / ABORT30% 이상 경고 / 50% 이상 중단WARN은 변경 검토, ABORT는 원문으로 복구

변경률 검사에서 종료 코드 1은 실행 오류가 아니라 WARN이다. v2.3.0 코드는 30% 미만이면 0, 30% 이상·50% 미만이면 1, 50% 이상이면 2를 반환한다. 파일이 없을 때의 3과 구분한다. 자동 처리에 연결할 때도 0이 아닌 값을 모두 파일 오류로 취급하지 말고 gate 출력과 함께 읽는다.

종료 코드 0만으로 진단 성공을 판단하지 않는다. 전처리기는 점수 계산에 실패해도 점수 없는 결합 입력을 만들고 정상 종료할 수 있다. degraded=False와 metrics 파일을 함께 확인해야 한다. route_hint는 수정 강도 권고이며 AI 작성 확률이나 문장 품질 점수가 아니다.

이 두 명령은 최종 윤문본을 만들지 않는다. 예시의 after.txt는 사람이 표현 두 군데를 바꾼 비교용 파일이다. AI 스킬을 쓸 때도 원문과 실제 윤문본을 같은 방식으로 대조하고 수치·이름·부정어를 따로 확인해야 한다. 낮은 변경률은 사실 보존의 증명이 아니다.

실제 윤문을 원한다면 v2.3.0 README의 Codex·Claude 설치 안내를 확인한다. install.sh는 사용자 스킬 경로에 연결을 만들므로 --dry-run으로 대상을 먼저 살핀다. Codex는 단일 호출, 다중 진단·finalize는 Claude Code용이다. 이번 보완에서도 전역 설치와 AI 호출은 실행하지 않았다.
