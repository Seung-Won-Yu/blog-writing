도메인 인증서 경보 메일은 대개 갱신이나 백업 인증서 때문에 온다. 그래서 받은편지함에서 넘기기 쉽지만, 누군가가 내 도메인을 포함한 인증서를 새로 발급받았다면 확인을 늦출 이유도 없다. Cloudflare는 8월 13일 Certificate Transparency Monitoring을 정식 제공으로 바꾸면서, 자사가 대신 발급한 인증서는 경보에서 자동으로 걸러 준다고 밝혔다. 남는 경보는 ‘무조건 사고’가 아니라, 발급 주체·DNS 이름·유효 기간을 빠르게 대조할 목록이 된다.

Certificate Transparency Monitoring 정식 제공과 인증서 경보 확인 방법

Cloudflare가 Certificate Transparency Monitoring을 정식 제공으로 전환하고, Cloudflare가 발급한 인증서는 자동으로 경보에서 제외한다고 알렸다.

경보 메일은 인증서 자체보다 먼저 세 항목을 묻는다

Certificate Transparency(CT)는 공개 TLS 인증서가 발급되거나 관찰될 때 그 존재를 공개 로그에 남겨, 누구나 CA의 발급 활동을 감사하고 의심스러운 발급을 알아차리게 하는 체계다. 로그는 오발급을 막지 않는다. 대신 이미 발급된 인증서가 숨기기 어려운 흔적을 남기므로, 도메인 소유자는 ‘내가 요청한 발급인가’를 확인할 출발점을 얻는다.

Cloudflare 문서는 모니터링을 기본 비활성(opt-in) 기능으로 설명한다. 켠 뒤에는 모니터링한 도메인을 덮는 인증서가 CA에서 발급돼 공개 CT 로그에 추가될 때 경보가 생긴다. 다만 Cloudflare가 사용자를 위해 발급한 인증서와 백업 인증서는 자동으로 걸러진다. 즉 경보가 왔다는 사실만으로 침해를 단정하지 말고, 자동 필터 뒤에 남은 외부 발급을 빠르게 대조해야 한다.

발급자·DNS 이름·유효 기간을 정상 기록과 대조한다

첫째는 Issuer, 즉 발급 CA다. 팀이 Let’s Encrypt 자동 갱신만 쓰는 도메인에 다른 CA가 나타났다면 요청 주체를 찾아야 한다. 둘째는 DNS 이름이다. 루트 도메인만 관리한다고 생각했는데 낯선 하위 도메인이나 예상하지 못한 SAN이 들어 있으면, 신규 서비스 연결인지 오발급인지 확인 대상이 된다. 셋째는 유효 기간이다. 정상 갱신 창과 맞지 않는 발급은 담당자와 배포 기록을 함께 확인한다.
