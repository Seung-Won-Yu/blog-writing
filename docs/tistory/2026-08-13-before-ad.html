MCP는 Stateless가 되고, 개발자는 이것이 다시 API가 되는지 묻는다

MCP 2026-07-28 명세의 stateless 전환이 세션 기반 원격 도구 서버의 라우팅과 운영을 어떻게 바꾸는지 다룬다.

세션이 사라지면 요청은 어느 서버로 가도 된다

이전 Streamable HTTP 방식에서는 먼저 initialize를 호출하고 서버가 준 Mcp-Session-Id를 이후 요청마다 들고 다녀야 했다. 2026-07-28에서는 이 초기 연결과 프로토콜 세션이 제거됐다. 도구 호출 하나가 필요한 버전과 기능 정보를 스스로 포함하므로, 로드밸런서는 그 요청을 특정 인스턴스에 고정하지 않아도 된다.

이 변화가 곧바로 ‘MCP는 평범한 API다’라는 뜻은 아니다. JSON-RPC 도구 호출, 클라이언트 기능 협상, 다중 왕복 요청 같은 MCP 고유의 규칙은 남는다. 바뀐 것은 이 규칙을 연결을 열 때 한 번 교환하느냐, 각 요청에서 선언하느냐이다.

초기 연결 대신 _meta가 맡는 정보

새 명세에서 프로토콜 버전과 클라이언트 기능은 요청의 _meta에 포함된다. 서버는 선언되지 않은 기능을 가정하면 안 되며, 필요한 기능이 없으면 오류로 돌려줘야 한다. 따라서 서버 코드에서 세션 객체에 숨겨 둔 기능 협상 결과가 있다면, 요청 검증 단계로 옮길 대상인지 먼저 점검해야 한다.
