1. 꽃 이름을 맞히는 일부터 시작하자

Iris는 붓꽃 150개의 측정값이 담긴 학습용 데이터다. 꽃마다 꽃받침 길이·너비, 꽃잎 길이·너비 네 값과 품종 이름이 있다. 네 측정값으로 품종을 맞히려는 것이 이번 목표다. 직접 사진을 모으거나 CSV를 내려받을 필요는 없다.

  • 특성: 예측할 때 넣는 정보. 여기서는 네 측정값이다.
  • 정답: 맞히려는 값. 여기서는 setosa·versicolor·virginica 세 품종이다.
  • 학습: 정답을 보며 규칙을 익히는 과정이다.
  • 평가: 배우는 데 쓰지 않은 꽃을 얼마나 잘 맞히는지 확인하는 과정이다.

품종처럼 종류를 고르면 분류, 가격처럼 숫자를 예상하면 회귀다. 정답 없이 비슷한 고객을 묶으면 군집화다. ‘AI를 써보자’보다 ‘무엇을 맞히거나 묶을 것인가’를 먼저 정하면 도구 선택이 쉬워진다.

Python 실습의 순서
① 꽃 150개를 학습용 120개와 최종 평가용 30개로 분리
② 학습용 120개 안에서 전처리·학습·검증을 5번 나눠 반복
③ 같은 분할에서 세 모델을 비교하고 후보 하나 선택
④ 그 후보만 별도로 남긴 30개로 최종 평가

②가 교차 검증이다. 학습용 120개를 다섯 묶음으로 나누고, 네 묶음으로 배우고 남은 한 묶음으로 확인하는 역할을 번갈아 수행한다. 별도로 남긴 30개는 모델 선택이 끝날 때까지 보지 않는다.

2. Orange에서는 ‘데이터’와 ‘처리 방법’을 따로 연결한다

Orange는 분석 블록을 선으로 잇는 도구다. 공식 Test and Score 안내를 기준으로 다음처럼 구성한다. 여기서는 교차 검증 흐름을 배우며, Python 경로와 동일한 점수가 나온다고 약속하는 실습은 아니다.

  1. File: 내장 예제 목록에서 iris를 불러온다. Data Table에 연결해 측정값 네 열과 품종 열을 확인한다. Data Table은 내용을 보는 가지이며 필수 중간 처리 단계는 아니다.
  2. Select Columns: 측정값 네 열은 Features, 품종 열은 Target에 둔다. 나오는 Data를 Test and Score의 Data 입력에 연결한다.
  3. Logistic Regression·Tree: 각 모델의 Learner 출력을 Test and Score의 Learner 입력에 연결한다. 학습된 Model 출력과 혼동하지 않는다.
  4. Preprocess: 정규화를 추가하고, Preprocessor 출력을 Test and Score의 Preprocessor 입력에 연결한다. 이 예제의 Iris에는 결측치가 없으므로 대체 단계는 필수가 아니다.
  5. Test and Score: Cross validation을 5 folds로 설정하고 층화(Stratified)를 켠다. 표의 CA·F1 등과 함께 잘못 맞힌 종류를 살펴본다.
  6. Confusion Matrix: Test and Score의 Evaluation Results를 연결한다. 행·열의 실제/예측 표시를 읽고 어떤 품종끼리 혼동했는지 확인한다.

가장 중요한 구분: Preprocess의 Preprocessed Data로 전체 데이터를 먼저 변환해서 평가기에 넣지 않는다. Preprocessor는 ‘처리 방법’이며, 평가기가 각 학습 묶음 안에서 그 방법을 학습하도록 전달해야 한다. 전체 데이터의 평균을 미리 쓰면 시험 문제의 정보를 먼저 본 셈이 된다.

이번 보완에서는 Orange 앱을 직접 실행해 측정하지 않았다. 위젯 연결은 공식 문서 대조 결과이며, 아래 수치는 Python 실행 결과다. Orange의 전체 클래스 요약 F1은 가중 평균이고 아래 코드는 품종마다 같은 비중을 주는 macro F1을 쓴다. 분할·기본 설정·집계 방식이 다르면 점수도 달라질 수 있다.

전체 실행 코드 펼치기 — ml152_iris.py 
"""Train-only model selection, then one untouched Iris holdout evaluation."""
import numpy as np
import sklearn
from sklearn.datasets import load_iris
from sklearn.dummy import DummyClassifier
from sklearn.ensemble import RandomForestClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score, confusion_matrix, f1_score
from sklearn.model_selection import StratifiedKFold, cross_validate, train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler


def run():
    iris = load_iris()
    train_ids, test_ids = train_test_split(
        np.arange(len(iris.target)), test_size=0.2,
        stratify=iris.target, random_state=42
    )
    X_train, y_train = iris.data[train_ids], iris.target[train_ids]
    X_test, y_test = iris.data[test_ids], iris.target[test_ids]
    folds = list(StratifiedKFold(
        n_splits=5, shuffle=True, random_state=42
    ).split(X_train, y_train))
    models = {
        "dummy": DummyClassifier(strategy="most_frequent"),
        "logistic": make_pipeline(
            StandardScaler(), LogisticRegression(max_iter=1000)
        ),
        "forest": RandomForestClassifier(
            n_estimators=100, random_state=42, n_jobs=1
        ),
    }
    print("scikit-learn:", sklearn.__version__)
    print("train / test:", len(train_ids), len(test_ids))
    print("train counts:", np.bincount(y_train).tolist())
    print("test counts:", np.bincount(y_test).tolist())
    results = {}
    for name, model in models.items():
        scores = cross_validate(
            model, X_train, y_train, cv=folds,
            scoring=["accuracy", "f1_macro", "recall_macro"]
        )
        results[name] = scores
        print(name)
        for metric in ("accuracy", "f1_macro", "recall_macro"):
            values = scores["test_" + metric]
            print(f"  {metric}: {values.mean():.3f} +/- {values.std():.3f}")
    # Toy rule: highest mean macro F1; tied scores keep dictionary order.
    chosen = max(results, key=lambda name: results[name]["test_f1_macro"].mean())
    model = models[chosen]
    model.fit(X_train, y_train)
    pred = model.predict(X_test)
    matrix = confusion_matrix(y_test, pred, labels=[0, 1, 2])
    print("chosen:", chosen)
    print(f"holdout accuracy: {accuracy_score(y_test, pred):.3f}")
    print(f"holdout macro F1: {f1_score(y_test, pred, average='macro'):.3f}")
    print("rows=actual, columns=predicted:", iris.target_names.tolist())
    print(matrix)
    return iris, train_ids, test_ids, folds, models, results, chosen, matrix


if __name__ == "__main__":
    run()

4. 정확도 98%인데 쓸모없을 수 있는 이유

앞의 가상 메일 100통으로 돌아가 보자. 모두 일반 메일이라고 답한 모델은 98통을 맞혔지만 실제 스팸 2통은 전부 놓쳤다. 이때 스팸 재현율은 0/2=0%다. 정확도와 ‘찾고 싶은 대상을 얼마나 찾았는가’는 다른 질문이다.

  • 정밀도: 스팸이라고 표시한 메일 중 실제 스팸의 비율. 일반 메일을 잘못 막는 일이 많으면 낮아진다.
  • 재현율: 실제 스팸 중 잡아낸 비율. 스팸을 많이 놓치면 낮아진다.
  • F1: 정밀도와 재현율의 조화평균. 두 지표를 함께 보려는 요약값이다.
  • macro 평균: 종류마다 점수를 계산하고 동일한 비중으로 평균한다. 적게 등장하는 종류도 똑같이 한 표를 갖는다.

스팸 예측이 0건이면 정밀도의 분모도 0이 된다. 라이브러리의 처리 규칙을 확인해야 하며 ‘정밀도가 완벽하다’고 읽으면 안 된다. 이번 Iris는 세 품종의 수가 같은 자료라서, 희귀 클래스 문제의 실증 자료로 쓰지는 않는다.

데이터 누수는 시험에 쓰일 정보가 공부 과정으로 들어가는 문제다. 평균·표준편차·결측치 대체값도 자료에서 배운 정보다. Python의 Pipeline은 전처리와 모델을 묶어, 교차 검증 때 학습 묶음으로만 그 값을 계산하게 한다.

5. 고객 데이터에 옮길 때는 ‘언제 알 수 있었나’를 묻자

꽃 실습 다음에 고객 이탈을 예측하고 싶어졌다고 하자. 목표는 ‘지금 가진 정보로 앞으로 떠날 고객을 찾기’다. 해지 뒤에 생긴 상담 기록이나 최종 상태를 넣으면 점수가 높아도 실제 예측에는 쓸 수 없다.

‘월 계약 고객이 더 많이 떠날 것이다’는 검증할 가설이지, 이 글에서 측정한 결과가 아니다. 자료의 기준일·이탈 정의·사용 가능한 열을 먼저 정하고 확인해야 한다. 상관관계를 봤다고 원인이라고 단정할 수도 없다.

  • 타이타닉처럼 정답이 있는 과거 사건을 맞히는 연습과, 미래 고객을 예측하는 운영 문제는 목적이 다르다.
  • 숫자 열은 결측치 처리·스케일링, 문자 열은 범주 변환이 필요할 수 있다. 실제 CSV의 자료형과 빈 값부터 확인한다.
  • 새 범주를 처리할 수 있다고 해서 모든 입력 오류가 해결되지는 않는다. 열 누락·잘못된 숫자·누수 여부는 별도 검사한다.
  • 시간이나 같은 고객의 반복 기록이 중요하면 무작위 분할만 쓰지 않는다. 과거/미래 또는 고객 그룹을 분리하는 평가가 필요할 수 있다.

여기서는 고객·타이타닉 CSV의 학습 결과를 제공하지 않는다. 입력 자료 없이 코드 몇 줄만 실행하면 같은 결과를 얻는다는 오해를 피하기 위해, 실행 실습은 내장 Iris 자료 하나로 제한했다.

6. 첫 모델은 왜 단순한 것으로 시작할까?

이번 실습의 로지스틱 회귀는 품종을 구분하는 단순한 기준 모델이다. 이름에 ‘회귀’가 있지만 여기서는 분류를 한다. 복잡한 모델과 비교할 기준이 있으면, 추가 비용에 비해 실제 개선이 있는지 판단하기 쉽다.

  • KNN: 가까운 자료의 정답을 참고한다. 길이와 금액처럼 단위가 다른 값을 함께 쓰면 거리 계산에 큰 단위가 과하게 영향을 줄 수 있다.
  • 결정 트리: 조건을 따라 가지를 나누는 방식이다. 규칙은 보기 쉽지만 너무 깊게 만들면 학습 자료의 예외까지 외울 수 있다.
  • 랜덤 포레스트: 여러 트리의 판단을 합친다. 이번 예제에서는 로지스틱 회귀보다 교차 검증 평균이 조금 낮았다. ‘앙상블이면 무조건 더 좋다’는 결론은 낼 수 없다.

문제 유형과 여러 모델을 합치는 방법의 개념 지도. 실제 성능 순위를 뜻하지 않는다.

7. 선택 심화: 앙상블은 여러 판단을 합친다

앙상블은 여러 모델의 결과를 합치는 방법이다. 하나를 늘리는 것보다, 함께했을 때 틀리는 양상이 줄어드는지 보는 것이 중요하다.

  • 배깅: 자료를 중복을 허용해 뽑은 여러 묶음으로 나눠 모델을 학습하고 합친다. 랜덤 포레스트는 여기에 분기마다 일부 특성 후보를 사용하는 무작위성도 더한다.
  • 부스팅: 앞 단계가 부족했던 부분을 보완하도록 다음 모델을 더한다. 설정에 따라 잡음까지 학습할 수 있어 검증이 필요하다.
  • 보팅: 여러 모델의 답을 다수결로 합치거나 확률을 평균한다. 예측 확률을 합칠 때는 그 확률이 얼마나 믿을 만한지도 확인한다.

포레스트 비교 코드는 이미 3절에 포함되어 있다. 다른 모델을 더하더라도 동일한 학습용 자료·동일한 검증 묶음·동일한 지표로 비교한다. 최종 평가용 30개까지 합쳐 다시 교차 검증하지 않는다.

8. 선택 심화: 정답 없이 비슷한 꽃을 묶으면?

K-means는 정답 이름을 보지 않고 가까운 자료끼리 묶는다. 각 자료를 가장 가까운 중심에 배정한 뒤, 그 묶음의 평균 위치로 중심을 옮기는 일을 반복한다. 묶음 수 k는 먼저 정한다.

별도 군집 실습 펼치기 — ml152_cluster.py

다음 코드는 앞 파일과 독립적으로 실행한다. 같은 가상환경에서 실행하며 꽃 150개 전체를 탐색하지만, 분류 모델의 학습·최종 평가에는 이 결과를 사용하지 않는다.

from sklearn.cluster import KMeans
from sklearn.datasets import load_iris
from sklearn.metrics import silhouette_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

X = load_iris().data  # 품종 정답은 쓰지 않는다.
clusterer = make_pipeline(
    StandardScaler(),
    KMeans(n_clusters=3, n_init=10, random_state=42)
)
labels = clusterer.fit_predict(X)
scaled_X = clusterer.named_steps["standardscaler"].transform(X)
print(f"silhouette: {silhouette_score(scaled_X, labels):.3f}")

3절의 가상환경 Python으로 ml152_cluster.py를 실행한 결과는 silhouette: 0.460이었다. 실루엣은 같은 묶음과 다른 묶음까지의 거리를 바탕으로 분리 정도를 요약하며 범위는 −1~1이다. 정확도 46%라는 뜻이 아니다. 기본/선택 실습의 분리와 코드 실행을 확인했으나 실제 고객 군집의 유용성은 측정하지 않았다.

군집 번호 0·1·2는 품종 번호나 순위가 아니다. k=3 역시 이 연습의 설정일 뿐 최선의 묶음 수를 증명하지 않는다. 실루엣 점수와 함께 실제로 설명할 수 있는 묶음인지 확인해야 한다. 일부 Mac 환경에서는 CPU 수 확인 경고가 뜰 수 있는데, 이 검증에서는 계산 결과는 정상 출력됐다.

9. 실행이 안 되거나 점수가 이상하면

  • sklearn을 찾지 못함: 설치한 가상환경의 Python으로 실행했는지 확인한다. 위 명령의 Python 경로를 설치와 실행에 동일하게 사용한다.
  • 파일을 찾지 못함: 현재 폴더에 ml152_iris.py가 있는지, 확장자가 .py.txt가 되지 않았는지 확인한다.
  • Windows에서 py 명령이 없음: Python 설치와 실행 경로부터 확인한다. 코드 문제와 실행 환경 문제를 구분한다.
  • 점수가 본문과 다름: 버전·데이터·랜덤 시드·폴드 수가 같은지 확인한다. 최종 테스트 점수와 교차 검증 평균을 같은 숫자로 기대하지 않는다.
  • 점수가 지나치게 높음: 정답 열이나 미래 정보가 입력에 들어갔는지, 전체 자료로 전처리를 먼저 학습했는지 검사한다.

10. 실습을 끝내는 세 가지 질문

  1. 무엇을 맞혔나? 꽃의 네 측정값으로 세 품종 중 하나를 골랐다.
  2. 공정하게 비교했나? 학습용 120개 안의 같은 검증 묶음으로 세 모델을 비교했고 전처리도 각 학습 묶음 안에서 배웠다.
  3. 어디서 틀렸나? 별도 30개 중 두 개를 틀렸고, versicolor와 virginica가 하나씩 서로 바뀌었다.

다음 연습에서는 학습용 자료의 교차 검증 오류를 먼저 살펴보자. 어떤 값이 겹쳐 보이는지 가설을 세우고, 한 가지 변경만 비교해 기록한다. 최종 평가 자료를 계속 들여다보며 설정을 맞추는 것은 피한다.

가져갈 것은 모델 이름보다 확인 순서다

정답을 정하고, 평가 자료를 따로 남기고, 전처리와 학습을 묶어 비교한다. 그다음 점수뿐 아니라 틀린 종류를 읽는다. 이 순서를 이해했다면 알고리즘 이름을 모두 외우지 않아도 이번 입문 실습의 목표는 달성한 것이다.
