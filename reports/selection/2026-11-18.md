# Codex Security SDK 검사 재개 원고 선정

11월 16일 Search Console 스냅샷의 유효 검색어 42개를 목록으로 확인했다. `codex security sdk`는 10월 17일~11월 13일에 0클릭·3노출, 직전 기간에 0클릭·0노출이었다. 사이트 검색어 합계이며 특정 글의 유입을 뜻하지 않는다.

[공개 172번](https://won0322.tistory.com/172)과 기존 원고 `2026-07-29`는 접근 조건과 설치, CI 도입, 결과 보관을 다룬다. 새 원고 `2026-11-18`은 이미 시작한 Standard 검사가 끊겼을 때 검사 ID로 상태를 확인하고 재개 또는 새 실행을 선택하는 별도 과제다. 11월 18일 후보함 재수집은 성공했고, 검색어에 맞는 11월 12일 변화를 공식 자료에서 별도로 확인했다. 기존 글 교체 대기본은 보존했다.

- [0.10.0 릴리스](https://github.com/openai/codex-security/releases/tag/npm-v0.10.0)와 [구현 변경](https://github.com/openai/codex-security/pull/2610)에서 저장된 ID·상태·누적 사용량·예산 유지와 취소·실패의 경계를 확인했다.
- [TypeScript SDK 안내](https://learn.chatgpt.com/docs/security/sdk)에서 연결 재시도 알림과 중단 시 부분 산출물을 확인했다. 실제 스캔·복구·비용 측정은 수행하지 않았다.
- PC 1280×900과 모바일 390×844에서 2열 표 안팎 700px·350px, 이미지 3장, 대표 축소, 코드와 광고 앞뒤 읽기 순서를 확인했다. 작은 영문 캡처의 핵심은 본문과 캡션에도 담았다.
