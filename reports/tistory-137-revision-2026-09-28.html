모집 공고, 품절 상품, 지원사업 신청 페이지는 궁금할 때마다 새로고침하게 만든다. 문제는 열 번 확인해도 아홉 번은 그대로라는 점이다. 이번 실험에서는 별도 유료 서비스나 계정 없이 Python 표준 라이브러리만으로 페이지의 핵심 문구를 저장하고, 다음 실행에서 값이 달라졌을 때만 ‘알림 대상’으로 표시하는 작은 감지기를 만들었다. 로컬 테스트 페이지를 ‘마감·0명’에서 ‘신청 가능·12명’으로 직접 바꿔 기준 저장, 변경 없음, 변경 감지, 대상 영역 누락까지 네 가지 흐름을 확인했다.

Python으로 웹페이지 변경 감지기를 직접 만들고 네 가지 상태를 검증한 기록

특정 영역의 텍스트만 저장해 이전 값과 비교하고, 달라진 실행에만 알림 신호를 만드는 구조를 실제 마감·신청 가능 페이지로 검증했다.

왜 새로고침 대신 변경 감지가 필요한가

모집 공고나 재고 페이지를 직접 확인하는 방식은 단순하지만 확인 횟수만큼 집중이 끊긴다. 반대로 페이지 전체를 1분마다 비교하면 날짜·추천 상품·방문자 수처럼 관심 없는 값에도 반응하고 상대 사이트에도 불필요한 요청을 만든다. 필요한 것은 ‘페이지가 조금이라도 달라졌는가’가 아니라 ‘내가 기다리는 신청 상태나 가격이 달라졌는가’를 판단하는 작은 장치다. 변경 감지와 알림 시스템에 관한 조사 연구도 동적인 웹페이지에서 수집, 변화 판정, 알림이 서로 다른 단계라는 점을 구분한다. 이 실험도 읽기와 비교, 알림 대상을 분리했다.

테스트 대상은 주말 사진 클래스 신청 카드다. 처음에는 ‘마감·0명·다음 확인’이 보이고, 나중에는 ‘신청 가능·12명·접수 마감’으로 바뀐다. 페이지의 머리글이나 배경은 비교하지 않고 id가 watch-target인 카드 속 글자만 읽는다. 이 선택 하나가 알림 품질을 좌우한다. 광고 배너나 시계처럼 자주 달라지는 요소가 감시 범위에서 빠지기 때문이다. 실제 사이트에서는 브라우저 개발자 도구로 원하는 영역의 고유 id나 CSS 선택자를 먼저 확인하면 된다.

전체 페이지가 아니라 핵심 문구만 비교한다

비교 범위는 좁을수록 좋지만 너무 좁으면 맥락을 잃는다. 가격 숫자 하나만 보면 통화나 옵션이 바뀌어도 놓칠 수 있고, 카드 전체를 보면 버튼 문구와 재고 수량을 함께 판단할 수 있다. 이번에는 카드 내부의 모든 텍스트를 줄 단위로 모은 뒤 연속 공백과 빈 줄을 제거했다. 같은 문장이 화면 폭 때문에 두 줄로 보이더라도 HTML 속 텍스트가 같으면 같은 값으로 처리한다. JavaScript로 나중에 그려지는 페이지, 로그인 뒤 화면, 무한 스크롤은 urllib만으로 읽히지 않을 수 있으므로 그때는 Playwright 같은 실제 브라우저 방식이 필요하다.

완성된 서비스가 필요하면 changedetection.io처럼 CSS 선택자, XPath, 브라우저 실행, 여러 알림 채널을 지원하는 공개 도구도 있다. 다만 작은 공개 페이지 한두 곳을 확인하는 목적이라면 Python 표준 라이브러리만으로 원리를 먼저 익혀 두는 편이 좋다. 무엇이 저장되고 어떤 변화가 알림을 만드는지 직접 볼 수 있고, 나중에 완성형 도구를 선택할 때도 필터와 확인 주기를 더 정확하게 정할 수 있다.

Python 표준 라이브러리로 직접 실험하기

준비물은 Python 3 하나뿐이다. urllib.request는 URL을 요청해 응답을 읽고, html.parser는 지정 영역의 글자를 모으며, hashlib.sha256은 정리된 텍스트를 짧고 고정된 값으로 바꾼다. SHA-256은 여기서 암호를 저장하려는 목적이 아니라 이전 내용과 현재 내용이 같은지 빠르게 비교하는 지문 역할을 한다. 원문도 state.json에 함께 남겨야 변경이 생겼을 때 어떤 줄이 달라졌는지 보여 줄 수 있다. 해시만 저장하면 변화 여부는 알 수 있지만 사람에게 설명할 차이를 만들기 어렵다.

처음 따라 한다면: Python 코드를 파일로 저장하고 터미널 명령을 실행할 수 있는 독자를 위한 예제다. 코딩 없이 알림 서비스를 쓰고 싶다면 앞의 changedetection.io 같은 도구부터 비교하면 된다. 아래 예제는 이메일·메신저를 보내지 않고 화면에 ‘알림 대상’만 출력한다.

서버 없이 세 번 실행해 보기

① 새 실험 폴더에서 아래 완전한 코드를 monitor.py로 저장한다. ② 같은 폴더에 demo.html을 만들고 아래 HTML을 UTF-8로 저장한다. 입력 HTML과 상태 파일은 반드시 다른 이름으로 둔다. 필요한 것은 Python 3이며 별도 패키지 설치는 없다.

<!doctype html>
<meta charset="utf-8">
<div id="watch-target">
  <p>마감</p>
  <p>0명</p>
</div>

③ 파일이 있는 폴더에서 같은 명령을 두 번 실행한다. Windows에서 python3 명령이 없다면 설치된 Python의 py -3로 바꾼다.

python3 monitor.py demo.html --html-file --state demo-state.json

첫 실행은 BASELINE, 두 번째는 UNCHANGED다. ④ demo.html에서 마감을 신청 가능으로, 0명을 12명으로 바꾸고 저장한 뒤 다시 실행한다. CHANGED와 바뀐 줄이 나온다. 네 번째에 다시 같은 파일을 읽으면 UNCHANGED로 돌아간다. 외부 웹사이트 요청이나 임시 서버 실행 없이 원리를 확인할 수 있다.

monitor.py 전체 코드 펼치기 — 이 부분을 모두 복사해 저장 
"""교육용 변경 감지기. UTF-8 HTML의 고유 id 하나만 비교한다."""
import argparse
import difflib
import hashlib
import json
import re
import sys
from html.parser import HTMLParser
from pathlib import Path
from urllib.parse import urlsplit
from urllib.request import Request, urlopen

LIMIT = 1_000_000
VOID = set("area base br col embed hr img input link meta param source track wbr".split())
BLOCK = set("div p li section article h1 h2 h3 h4 tr br".split())


class TargetText(HTMLParser):
    def __init__(self, target):
        super().__init__(convert_charrefs=True)
        self.target, self.stack, self.parts, self.matches = target, [], [], 0

    def handle_starttag(self, tag, attrs):
        matched = dict(attrs).get("id") == self.target
        if matched:
            self.matches += 1
            if self.stack or tag in VOID:
                raise ValueError("대상 id는 일반 컨테이너에 한 번만 사용하세요.")
            self.stack = [tag]
        elif self.stack and tag not in VOID:
            self.stack.append(tag)
        if self.stack and tag == "br":
            self.parts.append("\n")

    def handle_endtag(self, tag):
        if not self.stack or tag in VOID:
            return
        if self.stack[-1] != tag:
            raise ValueError("대상 내부의 HTML 종료 태그를 확인하세요.")
        self.stack.pop()
        if tag in BLOCK:
            self.parts.append("\n")

    def handle_data(self, data):
        if self.stack and not any(t in {"script", "style"} for t in self.stack):
            self.parts.append(data)

    def result(self):
        text = "\n".join(
            re.sub(r"\s+", " ", line).strip()
            for line in "".join(self.parts).splitlines() if line.strip()
        )
        if self.matches != 1 or self.stack or not text:
            raise ValueError("대상은 닫힌 태그·고유 id·비어 있지 않은 텍스트여야 합니다.")
        return text


def main():
    cli = argparse.ArgumentParser()
    cli.add_argument("source", help="HTTP(S) URL 또는 --html-file로 읽을 파일")
    cli.add_argument("--html-file", action="store_true")
    cli.add_argument("--target-id", default="watch-target")
    cli.add_argument("--state", default="state.json")
    args = cli.parse_args()
    state_path = Path(args.state)
    scope = [str(Path(args.source).resolve()) if args.html_file else args.source,
             args.target_id, args.html_file]
    try:
        if args.html_file:
            if Path(args.source).resolve() == state_path.resolve():
                raise ValueError("입력 HTML과 상태 파일은 다른 파일이어야 합니다.")
            with Path(args.source).open("rb") as stream:
                raw = stream.read(LIMIT + 1)
        else:
            if urlsplit(args.source).scheme not in {"http", "https"}:
                raise ValueError("공개 HTTP(S) URL만 입력하세요.")
            request = Request(args.source, headers={"User-Agent": "ChangeMonitorDemo/1.0"})
            with urlopen(request, timeout=10) as response:
                if response.headers.get_content_type() != "text/html":
                    raise ValueError("HTML 응답이 아닙니다.")
                raw = response.read(LIMIT + 1)
        if len(raw) > LIMIT:
            raise ValueError("HTML이 1MB 상한을 넘었습니다.")
        parser = TargetText(args.target_id)
        parser.feed(raw.decode("utf-8"))
        parser.close()
        current = parser.result()
        digest = hashlib.sha256(current.encode("utf-8")).hexdigest()
        previous = None
        if state_path.exists():
            previous = json.loads(state_path.read_text(encoding="utf-8"))
            if (not isinstance(previous, dict) or previous.get("scope") != scope
                    or not isinstance(previous.get("text"), str)
                    or previous.get("hash") != hashlib.sha256(
                        previous["text"].encode("utf-8")).hexdigest()):
                raise ValueError("상태 파일이 손상되었거나 다른 대상의 기준입니다.")
        status = ("BASELINE" if previous is None else
                  "UNCHANGED" if previous["hash"] == digest else "CHANGED")
        temp = state_path.with_name(state_path.name + ".tmp")
        # 한 대상에 한 프로세스만 실행한다. 임시 파일도 실험 전용 이름을 쓴다.
        with temp.open("x", encoding="utf-8") as stream:
            json.dump({"scope": scope, "hash": digest, "text": current},
                      stream, ensure_ascii=False, indent=2)
        temp.replace(state_path)
        print(status)
        if status == "CHANGED":
            print("알림 대상 (외부 전송 없음)")
            print("\n".join(difflib.unified_diff(
                previous["text"].splitlines(), current.splitlines(),
                fromfile="이전", tofile="현재", lineterm="")))
        return 0
    except (OSError, ValueError) as error:
        print("ERROR: " + str(error), file=sys.stderr)
        return 2


if __name__ == "__main__":
    raise SystemExit(main())

검증한 범위: 보완한 코드로 로컬 HTML의 최초 기준·동일 값·변경 값, 대상 누락·빈 대상·중복 id·태그 불일치·1MB 상한 초과, script/style 및 대상 밖 변경 제외, 손상된 상태 파일 보존을 다시 확인했다. 네트워크 실패는 모의 URLError로 시험했으며 실제 외부 사이트 접속 성공을 검증한 것은 아니다.

이 교육용 파서는 UTF-8 문서와 명시적으로 닫힌 컨테이너 태그, 고유 id 한 개를 전제로 한다. CSS로 숨긴 글자까지 정확히 판별하는 브라우저 렌더링이 아니며 script/style만 제외한다. 선택적 종료 태그·JavaScript 화면·다른 문자 인코딩의 사이트에는 그대로 적용하지 않는다.

Python 공식 urllib 문서는 Request에 헤더를 넣을 수 있고 urlopen 결과를 파일처럼 읽을 수 있다고 설명한다. 실제 감지기에는 timeout을 반드시 둬야 네트워크가 느릴 때 작업 전체가 멈추지 않는다. HTTPError와 URLError도 ‘페이지가 바뀌었다’로 처리하면 안 된다. 서버 오류나 연결 실패는 변화가 아니라 확인 실패다. 이번 스크립트는 감시 대상 영역이 없거나 요청에 실패하면 state.json을 덮어쓰지 않고 종료 코드 2를 반환하도록 만들었다. 다음 정상 실행에서 기존 기준과 비교할 수 있게 하기 위해서다.

 

첫 실행은 알림이 아니라 기준 저장이다

감지기를 처음 실행할 때는 비교할 과거가 없다. 이때 현재 페이지를 ‘새 변화’라고 알리면 시작하자마자 잘못된 알림이 온다. 그래서 상태 파일이 없으면 BASELINE을 기록하고 알림 없이 끝낸다. 두 번째 실행부터 이전 해시와 현재 해시를 비교한다. 같으면 UNCHANGED, 다르면 CHANGED다. 이번 전체 코드는 CHANGED일 때만 difflib으로 차이를 만들고 터미널에 출력한다. 이메일·텔레그램·슬랙 전송 기능은 포함하지 않으며 별도로 구현해야 한다.

전체 코드에서는 이전 기준의 대상 주소·id·해시를 함께 검사한다. 다른 대상에 같은 상태 파일을 재사용하거나 상태 파일이 손상되면 오류로 멈춘다. 확인 실패로 기준이 사라지지 않으며, 정상 비교가 끝났을 때만 새 기준을 저장한다.

  • BASELINE: 현재 값을 최초 기준으로 저장하고 알림은 보내지 않는다.
  • UNCHANGED: 이전 해시와 같으므로 기록만 남기고 조용히 끝낸다.
  • CHANGED: 달라진 줄을 만든 뒤 이 실행만 알림 대상으로 넘긴다.
  • ERROR: 연결 실패나 대상 누락은 기준을 덮어쓰지 않고 별도 오류로 남긴다.

HTTP 서버가 ETag나 Last-Modified를 잘 제공한다면 조건부 요청을 추가해 전송량을 줄일 수도 있다. MDN은 If-None-Match나 If-Modified-Since 조건이 맞을 때 서버가 304 Not Modified로 본문을 다시 보내지 않을 수 있다고 설명한다. 다만 304는 서버가 보는 리소스 단위의 변화 여부다. 페이지 전체 ETag가 바뀌어도 내가 보는 신청 카드는 같을 수 있으므로, 네트워크 절약용 조건부 요청과 의미 있는 텍스트 비교는 서로 대체 관계가 아니라 함께 쓸 수 있는 두 단계다.

마감에서 신청 가능으로 바꿔 본 실제 결과

아래 그림과 해시는 기존 로컬 웹 실험의 기록이다. 이번에 보완한 전체 코드는 같은 네 가지 판정을 로컬 파일로도 재현하며, 로그는 터미널에 텍스트로 출력한다. 원문 HTML과 정리 규칙이 달라지면 해시값도 달라지므로 숫자를 똑같이 맞추는 것이 아니라 판정 흐름을 확인한다.

로컬 서버를 연 뒤 첫 실행에서는 59d73bf72749로 시작하는 해시가 기준으로 저장됐고 알림은 없었다. 같은 페이지를 다시 읽은 두 번째 실행도 해시가 같아 UNCHANGED와 알림 없음으로 끝났다. 그다음 신청 상태를 마감에서 신청 가능으로, 남은 자리를 0명에서 12명으로, 다음 확인 문구를 접수 마감으로 바꿨다. 세 번째 실행의 해시는 1489a823f9da로 달라졌고 CHANGED와 알림 대상이 출력됐다. 단순히 ‘달라졌다’고만 쓰지 않고 빠진 줄은 붉게, 추가된 줄은 초록색으로 표시했다.

실제 사이트에 붙일 때 필요한 안전장치

로컬 실험은 원하는 만큼 실행해도 되지만 남의 사이트는 다르다. 먼저 이용 약관과 robots.txt, 공개 접근 가능 여부를 확인하고 로그인 우회나 차단 회피는 하지 않는다. 변화를 몇 초 안에 알아야 하는 특별한 이유가 없다면 확인 간격을 30분이나 1시간으로 두는 편이 낫다. 요청마다 알아보기 쉬운 User-Agent를 보내고 timeout과 재시도 상한을 정한다. 페이지 구조가 바뀌어 선택자가 사라지면 ‘품절 해제’가 아니라 오류로 멈춰야 한다. state.json에는 공개된 문구만 저장하고 계정 정보나 개인화된 응답은 남기지 않는다.

  • 감시 대상: 가격·재고·접수 상태처럼 행동을 바꾸는 문구만 고른다.
  • 확인 간격: 기본은 30분 이상, 사이트 정책과 정보 성격에 맞춰 늘린다.
  • 오류 분리: 404·500·연결 실패·선택자 누락을 CHANGED로 기록하지 않는다.
  • 알림 제한: 같은 변경을 반복 전송하지 않고 새 기준 저장 뒤 다시 비교한다.
  • 복구 방법: state.json을 백업하거나 삭제해 언제든 최초 기준 상태로 되돌린다.

정기 실행은 macOS와 Linux의 cron, Windows 작업 스케줄러, GitHub Actions 같은 도구에 연결할 수 있다. 개인 컴퓨터가 꺼져 있어도 돌아가야 한다면 서버나 Actions가 편하지만, 외부 사이트를 주기적으로 읽는 작업은 실행 환경의 고정 IP와 이용 정책을 함께 확인해야 한다. 처음에는 컴퓨터에서 하루 두세 번 수동 실행해 오탐이 없는지 보는 편이 안전하다. 알림 함수도 바로 붙이지 말고 CHANGED 로그가 원하는 순간에만 생기는지 먼저 확인한다.

수동 확인이 끝난 뒤 공개 사이트에 적용하려면 위 코드의 URL 입력 기능을 사용한다. 예를 들어 python3 monitor.py "공개 페이지의 실제 HTTP(S) URL" --target-id "실제 고유 id" --state live-state.json 형태다. 따옴표 속 문구는 실제 주소·id로 바꿔야 한다. 이 코드는 CSS 선택자나 로그인 쿠키를 지원하지 않는다. UTF-8 HTML의 초기 응답에 대상 id가 있어야 한다.

정기 실행은 수동 확인 후 별도로 설정한다. 대상마다 서로 다른 상태 파일을 사용하고 같은 파일에 두 프로세스를 동시에 실행하지 않는다. 저장 도중 실패해 .tmp가 남았다면 마지막 정상 상태 파일을 먼저 보존하고 임시 파일 내용을 확인한 뒤 따로 옮긴다. 손상된 기준을 오류 없이 새 기준으로 바꾸는 자동 복구는 하지 않는다.

페이지가 JavaScript로 렌더링되거나 버튼을 눌러야 값이 나타나면 urllib 대신 Playwright로 해당 요소의 textContent를 읽으면 된다. 수십 개 URL, 프록시, 로그인 단계, 이메일과 메신저 알림이 필요해지면 직접 만든 스크립트를 계속 키우기보다 changedetection.io 같은 검증된 도구를 비교하는 편이 유지보수에 유리하다. 작은 스크립트의 역할은 모든 기능을 대신하는 것이 아니라 내 문제에 필요한 변화 기준을 정확히 발견하는 데 있다.

변경 감지 자동화의 핵심은 페이지를 자주 읽는 기술보다 무엇을 변화로 인정할지 좁히는 기준에 있다. 전체 HTML이 아니라 의미 있는 카드의 텍스트만 정리하고, 첫 실행은 기준 저장으로 끝내며, 오류를 변화로 오인하지 않게 분리하면 불필요한 알림을 크게 줄일 수 있다. 실제 사이트에 적용할 때는 이용 약관과 robots 정책, 적절한 확인 간격을 먼저 확인하고 작은 대상 하나부터 시작하는 편이 안전하다.

직접 확인해보려면자주 새로고침하는 공개 페이지 한 곳에서 가격·접수 상태처럼 정말 필요한 문구 하나를 고르고, 30분 이상 간격으로 기준 저장과 변경 없음 흐름부터 시험해 보자.
