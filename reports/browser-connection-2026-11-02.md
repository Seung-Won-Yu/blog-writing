# 예약 브라우저 부재 진단과 연결 절차 보완

오늘 09:04 예약 기록은 `Browser is not available: iab`다. 현재 대화에서는 type iab가
제공됐고 제한 로컬 미리보기의 PC·모바일 캡처가 정상 동작했다. 콘텐츠·표·이미지가
실패한 것이 아니며 GitHub 인증 오류도 아니다. 예약에서 브라우저가 빠진 앱 내부의
정확한 원인은 이 자료만으로 확정하지 않는다.

현재 설치 설정에서 browser와 unified-computer-use 플러그인은 enabled다. 전역
권한이나 임의 환경 변수를 바꾸는 것은 이 차이를 해결했다는 증거가 아니므로 변경하지 않았다.
지원되는 open_in_codex browser 요청도 이번에는 queued를 반환했다. 숨겨진 대화의
패널 표시 대기는 실제 연결 성공이 아니다.

agent/BROWSER_QA.md와 WEEKLY_PIPELINE.md, 기존 예약 9·9-it·14의 앱 프롬프트를 보완했다.
현재 type iab ID 확인 → 빈 탭이면 새 탭 → 브라우저 부재면 호출 중인 대화의 정식 앱 패널
연결 요청 → 목록 재확인 → 조사·초안 저장 후 한 번 재확인 순서다. 준비되면 같은 실행에서
남은 검수를 이어가며, queued·브라우저 미제공·bind 실행 권한 오류·보안 거절을 구분한다.
명시적 보안 거절을 우회하거나 Chrome 전환·권한 완화·새 대화·추가 예약을 하지 않는다.

세 예약의 ACTIVE·09:00·gpt-6.1-sol/medium·검색어 우선·수동 티스토리 경계를 유지했다.
앱 API로 갱신한 뒤 저장된 TOML의 실제 값으로 재확인했다. 기존 전체 573개 회귀 검사를 통과했다. 저장소 문구만 바꾸고
예약도 갱신됐다고 보고하지 않는다.

현재 대화의 연결·PC/모바일 QA는 검증됐다. **무인 예약에서 이 연결 요청이 브라우저를
제공하는지는 아직 검증되지 않았다.** 앱이 계속 queued로 남으면 저장소 코드로 강제
연결할 수 없으며 이때의 최종 상태를 완료로 꾸미지 않는다. 변경은 지원되는 연결 요청과
재개 절차이며 ‘다음부터 무조건 안 막힘’의 보장이 아니다.
