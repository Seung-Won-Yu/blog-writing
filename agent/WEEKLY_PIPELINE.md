# 월~토 콘텐츠 파이프라인 운영 계약

이 문서는 예약 시각, 입력 원천, 요일별 선정 기준, 품질 검수, 사용자 인계 지점을
한곳에 고정한다. 개별 편집 계약은 글의 전개와 이미지 역할을 더 구체화하지만 이
문서의 시간·입력·발행 경계를 바꾸지 않는다.

## 시간과 발행 경계

- 월·수·금 06:30 KST: GitHub Actions가 후보만 수집·정규화·채점한다.
- 월~토 09:00 KST: Codex 예약 작업이 당일 역할의 조사·집필·이미지·검수·Pages
  도우미 준비를 시작한다.
- 10:00 KST 전후: 사용자가 완성 상태와 공개 미리보기를 다시 보고 티스토리에
  직접 붙여넣어 발행한다. 10시는 자동 예약 발행 시각이나 품질을 낮추는 마감이
  아니다.
- Codex와 GitHub Actions는 티스토리에 자동 발행하지 않는다.
- 09:00 예약은 월·수, 화·목처럼 역할이 같은 요일을 한 작업으로 묶어도 된다.
  같은 요일을 별도 작업으로 다시 만들거나 재시도 예약을 추가하지 않는다.

GitHub 예약 실행은 정각보다 늦게 시작될 수 있다. 수집을 06:30에 시작해 09:00
편집 전 150분을 확보한다. 09:00에 당일 후보함이 없거나 오래됐으면 해당 수집기를
같은 실행에서 한 번만 다시 돌린다. 그래도 준비되지 않으면 오래된 후보를 쓰지 않고
같은 요일 역할의 공개 공식 자료·표준·원 논문·독립 자료를 직접 조사한다.

월요일과 수요일은 같은 원천을 보더라도 `weekly_lane_score`의 가중치와 최소
통과선을 모두 다르게 적용한다. 화·목은 유행 뉴스가 아니라 오래가는 질문을 직접
찾으므로 Git 후보 수집기를 억지로 붙이지 않는다. 금요일은 개발·AI 전용 100점
수집기, 토요일은 실제 비공개 프로젝트 증거가 우선이므로 다른 요일 후보함을 섞지
않는다.
화·목·토는 별도 Git 수집기를 추가하는 대신 선택 점수와 하드 게이트를
`editorial.selection_evaluation`에 기록한다. 가드는 기준별 상한·합계·통과선·
요일 전용 0점·게이트를 다시 계산해 문서에만 있는 점수표가 되지 않게 한다.

## 09:00 편집과 품질 인계

1. 저장소 동기화와 당일 가드로 `NEW`, `PARTIAL`, `COMPLETE`를 판정한다.
2. 당일 역할과 입력 원천이 맞는지 확인하고 중복·출처·날짜를 먼저 거른다.
3. 첫 후보가 탈락하면 같은 역할 안에서 재수집 또는 직접 리서치를 한 번 확장한다.
4. 요일별 독자 약속과 이미지 약속으로 원고·이미지를 만들고 독자 이해도와 공개
   가독성 모두 8.5 이상이 될 때까지 같은 실행에서 재편집한다.
5. 가드·발행 묶음·데스크톱·모바일·테스트를 통과한 결과만 커밋·푸시한다.
6. GitHub Pages의 `오늘 글 발행 준비` 카드에 제목·카테고리·태그·대표 이미지·
   광고 조립·미리보기·최종 HTML이 모두 연결되면 사용자에게 인계한다.

품질 기준을 끝내 충족하지 못한 날은 빈도를 채우려고 약한 글을 만들지 않는다.
`NO_PUBLISH_QUALITY` 또는 `NO_PUBLISH_EVIDENCE`와 실제 검토 범위를 남기며,
사용자에게 같은 실패를 다시 시키는 단순 재실행 예약은 만들지 않는다.
