# 독자가 찾아올 이유 — 2026-09-29 신규 원고부터

이 계약은 전 요일에 적용한다. 기존 글을 자동 삭제하거나 옛 원고의 검수를 소급 실패시키지 않는다.
8.5/10 같은 자동 점수는 구조 신호다. 독창성·사람의 만족·검색 유입·AdSense 승인을 측정하지 않는다.

## 선정 전에 결정할 것

후보 점수가 높아도 먼저 주 독자 한 명, 질문 하나, 출처만 읽으면 남는 공백,
그 공백을 채울 본문의 구체적 기여를 정한다. 제목만 다른 중복 질문은 기존 글 보완 대상으로 돌린다.
월: 재현 조건과 해결·실패 경계. 화: 일상 장면에서 원리를 이해할 예와 안전한 확인법.
수: 영향 받는 사람/받지 않는 사람과 지금 필요한 행동. 목: 믿음의 사실 경계와 근거.
금: 특정 사용 상황에서 무엇을 선택하고 생략할지. 토: 실제 구현의 선택·결과·한계.
수집기 점수는 후보 정렬만 담당한다. 이 기여를 설명할 수 없으면 조사 대상을 바꾼다.

## 집필

- 도입에서 제목의 답을 먼저 준다. 같은 답을 요약·본문·결론에서 반복해 분량을 채우지 않는다.
- 용어는 필요한 시점에 설명한다. 그림·표·코드는 독자의 이해에 필요한 경우만 추가한다.
- 공식 근거를 재구성한 설명도 가치가 있을 수 있다. 모든 글에 실험을 강요하지 않는다.
- 직접 측정하지 않은 속도·가격·성과 비교를 체험으로 쓰지 않는다. 가상 예는 예시라고 표시한다.
- 실제 관찰, 문헌 사실, 작성자의 해석을 구분한다. 해석에는 본문에서 해석임을 밝힌다.
- imagegen 그림/카툰은 설명용이다. 실제 UI, 실험 사진, 측정값의 증거로 취급하지 않는다.
- 기존 필수 필드를 채우기 위해 본문에 결론을 복제하지 않는다. 공통 구조와 시각 검수는 유지한다.

## 근거 연결 기록

`editorial.value_review`에 `primary_reader`, `reader_question`, `source_gap`,
`selection_reason`을 작성한다. `contributions`에는 다음 객체를 하나 이상 둔다.

```json
{
  "basis": "documented",
  "excerpt": "실제 본문 문단 또는 목록에 있는 기여 문장을 그대로 기록",
  "limit_excerpt": "실제 본문에 있는 적용 한계 문장을 그대로 기록",
  "source_urls": ["news[].references에 등록된 공개 HTTPS 원문 URL"]
}
```

`basis`는 `documented`(문헌), `observed`(실제 확인), `inference`(해석) 중 하나다.
observed에는 검토 가능한 실행 로그·캡처·테스트 식별자를 `observation_record`로 추가한다.
비공개 프로젝트의 원문·식별자는 공개 원고에 넣지 말고 공개 안전한 관찰 요약과 증거 별칭을 쓴다.
inference에는 본문에서 해석임을 밝힌 문장을 `disclosure_excerpt`로 추가한다.
가드는 본문 연결과 참조 존재를 검사할 뿐 출처의 진실성이나 기여의 독창성을 보증하지 않는다.
편집자가 실제 원문과 관찰 기록을 읽어 검증해야 한다. 임의로 검수 완료를 표기하지 않는다.

## 같은 실행의 보완

`quality_value_review`가 나오면 누락 필드를 꾸미지 말고 본문과 근거부터 보완한다.
근거 부족 시 추가 리서치, 중복 시 같은 요일의 다음 후보로 전환한다.
같은 결함이 두 번 반복되면 해당 절을 다시 설계한다. 끝내 근거가 없으면 초안을 보존하고
정확한 미완료 사유를 알린다. 발행을 위해 경험을 꾸미거나 보안·QA를 우회하지 않는다.

## 공개 글 점검과 재신청

자동 감사 0건은 승인 준비 완료가 아니다. 최근 대표 글과 오래된 글의 실제 본문을 읽고
유지/보완/통합 검토 및 이유를 기록한다. 공개 모바일에서 이미지·링크·광고 간섭도 확인한다.
사용자 허락 없이 삭제·비공개·광고 설정 변경·AdSense 재신청은 하지 않는다.
